# [Design] 오행 포토부스 (키오스크)

> `오행포토부스.plan.md` 기반 상세 설계 — DB 스키마, API, 컴포넌트, 세그멘테이션·합성 파이프라인

---

## 1. 라우트 구조

기존 `(shop)` / `(admin)` 레이아웃과 분리된 신규 route group `(kiosk)`를 사용한다. 헤더/푸터/장바구니 등 쇼핑몰 UI를 전부 제거하고, 풀스크린·세로 모바일 전용 레이아웃으로 구성한다.

```
app/
├── (kiosk)/
│   ├── layout.tsx              # 풀스크린, max-w-md 고정, 상단 네비 없음
│   └── kiosk/
│       ├── page.tsx            # ① 인트로
│       ├── birth/page.tsx      # ② 생년월일 입력
│       ├── capture/page.tsx    # ③ 동의 → 카운트다운 → 촬영
│       └── result/page.tsx     # ④ 합성 결과 + QR
├── p/[id]/page.tsx              # QR 스캔 후 도착하는 공개 페이지 (kiosk 레이아웃 밖, 방문자 개인 폰에서 열림)
└── api/kiosk/
    ├── photo/route.ts           # POST 업로드
    └── photo/[id]/route.ts      # GET 조회

```

세션 상태(생년월일 → 오행 → 촬영 이미지)는 서버 저장 없이 클라이언트에서만 유지한다 (`sessionStorage` 또는 페이지 이동 대신 단일 페이지 내 단계 전환 방식도 가능 — 아래 "대안" 참고). 키오스크 특성상 새로고침/뒤로가기가 거의 없으므로 URL 단계 분리보다 **단일 페이지 내 단계(step) 상태 전환** 방식이 더 견고하다.

> **설계 결정**: `app/(kiosk)/kiosk/page.tsx` 하나에서 `step: "intro" | "birth" | "consent" | "capture" | "processing" | "result"` 상태로 전체 플로우를 관리한다 (기존 `saju/page.tsx`가 결과를 같은 페이지 내에서 상태로 다루는 것과 동일한 패턴). 위 라우트 표의 `birth/`, `capture/`, `result/` 는 실제로는 별도 URL이 아니라 하나의 페이지 내부 화면 전환으로 대체 — URL 분리가 필요 없다면 만들지 않는다 (Simplicity First).

## 2. DB 스키마 (Prisma)

방문자 사진은 비회원 데이터이며 개인정보 보관 기간 정책이 필요하므로, 최소한의 만료 관리용 테이블만 추가한다.

```prisma
// prisma/schema.prisma 에 추가

model KioskPhoto {
  id        String   @id @default(cuid())
  ohaeng    String   // "목" | "화" | "토" | "금" | "수"
  imageUrl  String   // Vercel Blob URL
  createdAt DateTime @default(now())
  expiresAt DateTime // createdAt + 48h (정책값은 lib/kiosk/constants.ts 에서 관리)
}
```

- 런타임 조회는 기존 `app/api/saju/analyze`와 동일하게 **Supabase JS client**(`lib/supabase.ts`)로 처리한다 (Prisma는 스키마/마이그레이션 용도로만 사용하는 기존 프로젝트 관례를 따름).
- 주문/유저와 연결하지 않는다 (비회원 플로우, 이번 범위 제외).

## 3. API Routes

### 사진 업로드

| Method | Path | 설명 |
|--------|------|------|
| POST | `/api/kiosk/photo` | 합성된 이미지(Blob/base64) + 오행 → Vercel Blob 업로드 + `KioskPhoto` 레코드 생성 |

```typescript
// POST /api/kiosk/photo
// Request: multipart/form-data
//   file: Blob (image/jpeg, canvas.toBlob 결과)
//   ohaeng: "목" | "화" | "토" | "금" | "수"

// Response
{
  id: "clx...",
  url: "https://...blob.vercel-storage.com/kiosk/clx....jpg"
}
```

내부 흐름:
1. `@vercel/blob`의 `put(\`kiosk/${nanoid()}.jpg\`, file, { access: "public" })` 로 업로드
2. `supabaseAdmin.from("KioskPhoto").insert({ ohaeng, imageUrl, expiresAt })` — `expiresAt = now + 48h`
3. `{ id, url }` 반환 → 클라이언트는 `id`로 QR 대상 URL(`/p/[id]`) 구성

### 사진 조회 (QR 도착 페이지용)

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/kiosk/photo/[id]` | 만료 확인 후 이미지 URL 반환. 만료 시 404 |

`app/p/[id]/page.tsx` (서버 컴포넌트)가 이 API를 호출해 이미지를 표시하고, "사진 저장하기"(다운로드) 버튼과 Web Share API 공유 버튼을 제공한다 (`ShareCard.tsx`의 `downloadCard`/`shareToWeb` 패턴 재사용).

### 정리(Cleanup)

| Method | Path | 설명 |
|--------|------|------|
| POST | `/api/kiosk/cleanup` | 만료된 `KioskPhoto` 레코드 + Blob 파일 삭제. Vercel Cron으로 1일 1회 호출 |

`vercel.json`에 cron 등록 (예: 매일 04:00 KST). MVP 단계에서는 수동 운영도 가능하나, 얼굴 사진이 포함되므로 늦어도 Phase 6에서는 자동화한다.

## 4. 오행 분석 재사용

새 로직을 만들지 않고 `lib/saju.ts`를 그대로 가져다 쓴다.

```typescript
import { analyzeOhaeng, OHAENG_PROFILE } from "@/lib/saju"

const ohaeng = analyzeOhaeng(birthDate)      // "목" | "화" | "토" | "금" | "수"
const profile = OHAENG_PROFILE[ohaeng]        // colors, keywords, flowerKeywords, description
```

키오스크에서는 `calculateSaju()`의 4주(연/월/일/시) 상세 결과는 노출하지 않는다 — 시간 입력까지 요구하면 키오스크 체험이 길어지므로, **생년월일만 입력받아 `analyzeOhaeng()`으로 일간 오행만 산출**한다 (`BirthDateForm.tsx`보다 입력 필드가 적은 `BirthDateQuickForm.tsx` 신규 작성).

## 5. 카메라 촬영 (`components/kiosk/CameraCapture.tsx`)

```typescript
// 흐름
1. navigator.mediaDevices.getUserMedia({ video: { facingMode: "user" }, audio: false })
2. <video> 엘리먼트에 스트림 바인딩, 실시간 프리뷰
3. "촬영하기" 탭 → 3-2-1 카운트다운 오버레이
4. 카운트다운 종료 시 hidden <canvas>에 현재 video 프레임을 drawImage
5. canvas → ImageBitmap (세그멘테이션 입력으로 사용)
6. 스트림 트랙 정지 (getTracks().forEach(t => t.stop()))
```

- 권한 거부/미지원 브라우저: 안내 화면 + "다시 시도" 버튼만 제공 (재시도 로직은 브라우저 새 권한 프롬프트에 위임)
- HTTPS 필수 (getUserMedia 브라우저 제약) — 배포 환경(Vercel)은 기본 충족

## 6. 인물 분리 + 배경 합성 파이프라인

### 6-1. 세그멘테이션 (`lib/kiosk/segmentation.ts`)

`@mediapipe/tasks-vision`의 `ImageSegmenter` (Selfie Segmenter 모델)를 사용한다. 실시간 비디오 세그멘테이션이 아니라 **캡처된 정지 프레임 1장만 처리**하면 되므로 지연 시간 부담이 적다.

```typescript
import { ImageSegmenter, FilesetResolver } from "@mediapipe/tasks-vision"

let segmenterPromise: Promise<ImageSegmenter> | null = null

async function getSegmenter() {
  if (!segmenterPromise) {
    segmenterPromise = (async () => {
      const files = await FilesetResolver.forVisionTasks(
        "https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision/wasm"
      )
      return ImageSegmenter.createFromOptions(files, {
        baseOptions: {
          modelAssetPath:
            "https://storage.googleapis.com/mediapipe-models/image_segmenter/selfie_segmenter/float16/latest/selfie_segmenter.tflite",
          delegate: "GPU",
        },
        outputCategoryMask: false,
        outputConfidenceMasks: true, // 인물 확률 마스크(0~1) 사용 → 알파값으로 직접 활용
      })
    })()
  }
  return segmenterPromise
}

export async function segmentPerson(image: ImageBitmap) {
  const segmenter = await getSegmenter()
  const result = segmenter.segment(image)
  return result.confidenceMasks![0] // Float32Array, 인물일 확률
}
```

- 모델은 최초 진입 시 1회 다운로드/캐싱 (수 MB) — 키오스크는 상시 켜진 태블릿이므로 최초 로딩 이후에는 재다운로드 없음 (브라우저 캐시)
- `outputConfidenceMasks`를 사용해 0~1 확률값을 그대로 알파 채널로 사용하면 머리카락 등 경계가 자연스럽게 페더링됨 (이진 마스크보다 우선 채택)

### 6-2. 합성 (`lib/kiosk/compositeCanvas.ts`)

```typescript
export async function compositePhoto(
  personImage: ImageBitmap,
  mask: Float32Array,       // segmentPerson() 결과, 인물 확률(0~1)
  backgroundUrl: string,    // 오행별 배경 이미지 경로
  canvas: HTMLCanvasElement
) {
  const ctx = canvas.getContext("2d")!
  canvas.width = personImage.width
  canvas.height = personImage.height

  // 1) 배경 이미지를 cover 방식으로 그리기
  const bg = await loadImage(backgroundUrl)
  drawCover(ctx, bg, canvas.width, canvas.height)

  // 2) 인물 레이어를 offscreen canvas에 그린 뒤, mask를 알파로 적용
  const personCanvas = new OffscreenCanvas(canvas.width, canvas.height)
  const pctx = personCanvas.getContext("2d")!
  pctx.drawImage(personImage, 0, 0)
  const imgData = pctx.getImageData(0, 0, canvas.width, canvas.height)
  for (let i = 0; i < mask.length; i++) {
    imgData.data[i * 4 + 3] = Math.round(mask[i] * 255) // alpha = 인물 확률
  }
  pctx.putImageData(imgData, 0, 0)

  // 3) 배경 위에 인물 레이어 합성
  ctx.drawImage(personCanvas, 0, 0)

  // 4) 오행 뱃지/로고 오버레이 (선택)
  drawBadge(ctx, canvas.width, canvas.height)

  return new Promise<Blob>((resolve) =>
    canvas.toBlob((blob) => resolve(blob!), "image/jpeg", 0.92)
  )
}
```

- `drawCover`: 배경 이미지를 캔버스 비율에 맞게 크롭/확대해 채우는 유틸 (object-fit: cover와 동일한 로직)
- 결과 `Blob`을 그대로 `FormData`에 담아 `/api/kiosk/photo`로 업로드

### 6-3. 오행별 배경 매핑 (`lib/kiosk/backgrounds.ts`)

```typescript
import type { Ohaeng } from "@/lib/saju"

export const KIOSK_BACKGROUNDS: Record<Ohaeng, string[]> = {
  목: ["/kiosk-backgrounds/mok_1.jpg", "/kiosk-backgrounds/mok_2.jpg"],
  화: ["/kiosk-backgrounds/hwa_1.jpg", "/kiosk-backgrounds/hwa_2.jpg"],
  토: ["/kiosk-backgrounds/to_1.jpg", "/kiosk-backgrounds/to_2.jpg"],
  금: ["/kiosk-backgrounds/geum_1.jpg", "/kiosk-backgrounds/geum_2.jpg"],
  수: ["/kiosk-backgrounds/su_1.jpg", "/kiosk-backgrounds/su_2.jpg"],
}

export function pickBackground(ohaeng: Ohaeng): string {
  const list = KIOSK_BACKGROUNDS[ohaeng]
  return list[Math.floor(Math.random() * list.length)]
}
```

배경 이미지는 **런타임에 AI로 생성하지 않고, 사전에 검수된 정적 이미지**를 사용한다 (`/custom` 기능이 사용하는 Pollinations.ai 실시간 생성 방식과 다름). 이유:
- 키오스크는 초당 처리 속도와 안정성이 중요 — 외부 생성 API의 10~30초 지연/실패율은 현장 체험에 부적합
- 오행별 색감/구도를 사전에 디자인 검수해 톤 일관성 확보 가능

배경 이미지 소스는 `/custom` 기능과 동일하게 Pollinations.ai(`flux-realism`)로 **사전 제작**한 뒤 `public/kiosk-backgrounds/`에 정적 파일로 저장하는 방식을 권장 (1회성 생성 작업, 런타임 호출 아님).

## 7. 결과 화면 + QR (`components/kiosk/ResultShare.tsx`)

```
1. compositePhoto() 결과 Blob을 미리보기로 표시
2. "저장하고 QR 받기" 버튼 → POST /api/kiosk/photo (FormData: file, ohaeng)
3. 응답의 id로 `${origin}/p/${id}` URL 구성
4. react-qr-code로 QR 렌더링 (기존 의존성 재사용)
5. "다시 촬영하기" / "처음으로" 버튼 제공
6. 결과 화면 진입 후 60초 유휴 시 자동으로 인트로(step="intro")로 복귀 (다음 방문객을 위한 리셋)
```

`app/p/[id]/page.tsx`는 일반 모바일 브라우저(방문자 개인 폰)에서 열리는 페이지로, `ShareCard.tsx`의 다운로드/공유 버튼 패턴을 그대로 재사용한다.

## 8. 개인정보 동의 (`components/kiosk/ConsentScreen.tsx`)

촬영 전 필수 고지 화면:

```
"촬영된 사진은 오행 꽃 배경과 합성되어 QR로 제공되며,
합성 이미지는 48시간 후 자동 삭제됩니다.
[동의하고 촬영하기]  [취소]"
```

- 동의 없이는 `getUserMedia` 호출 자체를 하지 않음
- 서버에는 원본 촬영본을 저장하지 않고, **합성 완료된 이미지만** 업로드한다 (원본 인물 사진 단독 보관 안 함 → 개인정보 리스크 최소화)

## 10. 성공 기준 (Design 기준)

- [ ] `KioskPhoto` 모델 마이그레이션 정상 반영
- [ ] `/api/kiosk/photo` 업로드 → Blob URL + `id` 정상 반환
- [ ] `/p/[id]` 접근 시 만료 전에는 이미지 정상 표시, 만료 후에는 안내 메시지
- [ ] 오행 5종 × 배경 2종 이상 합성 결과 육안 검수 통과
- [ ] 모바일(세로) 375~430px 뷰포트에서 전 화면 정상 동작
- [ ] 촬영 동의 없이는 카메라 권한 요청이 발생하지 않음
- [ ] Vercel Cron 기반 만료 데이터 정리 동작 확인

## 11. 향후 발전 과제 (이번 범위 제외)

- 4컷 스트립(다중 촬영 + 그리드 레이아웃) — "인생네컷" 브랜드에 더 충실한 형태
- 결과 화면에 "이 꽃 배경의 꽃다발 주문하기" CTA 추가 → `/custom` 또는 상품 상세로 연결 (Feature D 합류)
- 구매자 QR 연동(Feature D)과의 통합 — 구매 시 포토부스 우선 입장 등 프로모션 연계
- 배경 이미지에 계절 변수 추가 (오행 × 계절 조합)
