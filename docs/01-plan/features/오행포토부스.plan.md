# [Plan] 오행 포토부스 (키오스크)

> 인생네컷 스타일의 모바일 웹 키오스크 — 생년월일 입력 → 오행 분석 → 촬영 → 오행에 어울리는 꽃 배경 합성 → QR로 사진 저장
> 기존 `인생내꽃.plan.md`의 **Feature D (오프라인 포토부스 연동)** 를 구체화한 문서. 기존 PC 쇼핑몰과는 별개의 모바일 전용 경험으로 설계한다.

---

## 1. 개요 (Overview)

### 배경

기존 인생내꽃 플랫폼은 PC 웹 쇼핑몰 중심이며, `saju/` 페이지에서 생년월일 기반 오행 분석과 꽃 추천을 이미 제공한다. 이번 기능은 그 오행 분석 로직(`lib/saju.ts`)을 재사용하되, 매장 현장의 키오스크(태블릿/모바일 브라우저)에서 동작하는 **별도의 모바일 웹 경험**을 새로 만든다.

- 참고 모델: "인생네컷" 등 즉석 포토부스 — 다만 그린스크린 촬영이 아니므로, 배경 합성은 소프트웨어적으로 처리한다.
- 방문객은 로그인 없이 즉석에서 체험하며, 결과물은 QR 코드로 각자 휴대폰에 저장한다. (구매/장바구니 연동은 이번 범위에 포함하지 않음 — 향후 과제로 분리)

### 핵심 플로우

```
[인트로 화면] → [생년월일 입력] → [오행 분석 (재사용: lib/saju.ts)]
     ↓
[촬영 동의 + 카메라 촬영] → [인물 분리 + 오행 꽃 배경 합성]
     ↓
[결과 미리보기] → [QR 코드 생성 (사진 저장용)] → [일정 시간 후 인트로로 자동 복귀]
```

### 기존 Feature D와의 관계

| 구분 | 기존 Feature D (plan 문서) | 이번 기능 (오행 포토부스) |
|------|---------------------------|--------------------------|
| 트리거 | 구매 후 QR 스캔 (구매자 전용) | 누구나 바로 체험 (비회원, 비구매) |
| 배경 | "구매한 꽃"을 배경으로 표시 | 오행 분석 결과에 맞는 꽃 배경을 합성 생성 |
| 결과물 | 매장 하드웨어로 촬영 지원 | 모바일 웹에서 촬영·합성·저장까지 전부 처리 |
| 목적 | 구매 연계 체험 | 유입/바이럴용 단독 체험 (구매 연동은 향후 과제) |

두 기능은 배타적이지 않으며, 이번 기능이 먼저 단독으로 동작하도록 만들고, 이후 "이 꽃 배경으로 꽃다발 주문하기" 같은 CTA를 붙여 Feature D와 합류시킬 수 있다.

## 2. 핵심 기능

### Feature A: 생년월일 → 오행 분석 (재사용)

`lib/saju.ts`의 `analyzeOhaeng()` / `calculateSaju()`를 그대로 재사용. 키오스크에서는 터치 친화적인 간소화 입력폼만 새로 만든다 (연주/월주/시주 등 상세 결과는 노출하지 않고, 최종 오행 1개 + 대표 색상/꽃 키워드만 사용).

### Feature B: 카메라 촬영

- `getUserMedia`로 전면 카메라 기본 활성화 (후면 전환 옵션)
- 3-2-1 카운트다운 후 자동 캡처
- 촬영 전 개인정보 동의 화면 필수 (촬영 사진의 보관 기간 안내 후 "동의하고 촬영" 진행)

### Feature C: 인물 분리 + 꽃 배경 합성

- 클라이언트 사이드 인물 세그멘테이션(브라우저 내 WASM 모델)으로 인물만 분리
- 오행별로 미리 준비된 꽃 배경 이미지 위에 인물을 합성 (Canvas API)
- 상세 기술 방식은 `오행포토부스.design.md` 참고

### Feature D: 결과 저장 (QR)

- 합성된 이미지를 서버에 업로드 후, 다운로드 페이지로 연결되는 QR 코드 생성 (기존 `qrcode` / `react-qr-code` 의존성 재사용)
- 방문자는 자신의 폰으로 QR을 스캔해 사진을 저장
- 저장된 사진은 일정 기간 후 자동 삭제 (개인정보 보호)

### 이번 범위에 포함하지 않는 것

- 구매/장바구니 연동, 결제 연동
- 회원가입/로그인 연동 (완전 비회원 플로우)
- 4컷 스트립(다중 촬영) — 1차는 1컷 합성으로 파이프라인 검증 후 향후 과제로 확장

## 3. 기술 스택 (기존 스택에 추가)

| 분류 | 선택 | 이유 |
|------|------|------|
| 인물 세그멘테이션 | `@mediapipe/tasks-vision` (Selfie Segmenter) | 브라우저 WASM 실행, 무료, 단일 프레임 처리 속도가 빨라 키오스크 회전율에 적합 |
| 이미지 합성 | Canvas API (직접 구현) | 마스크 알파 합성에 세밀한 제어 필요 (html2canvas는 DOM 캡처용이라 부적합) |
| 결과 업로드 | `@vercel/blob` (신규 의존성 추가 필요) | 이미 `BLOB_READ_WRITE_TOKEN` 환경변수 존재, 기존 스택과 일관성 |
| QR 코드 | `qrcode` / `react-qr-code` (기존 의존성) | 이미 설치되어 있음 |
| DB 조회 | Supabase JS client (`lib/supabase.ts`) | 기존 `app/api/saju/analyze`가 Prisma가 아닌 Supabase client로 조회하는 패턴을 따름 |

## 5. 개발 단계 (Phases)

| Phase | 내용 | 검증 기준 |
|-------|------|-----------|
| Phase 1 | 생년월일 입력 → 오행 분석 재사용 화면 | 오행 결과가 `lib/saju.ts`와 동일하게 도출 |
| Phase 2 | 카메라 촬영 (동의 → 카운트다운 → 캡처) | 촬영된 프레임이 canvas에 정상 표시 |
| Phase 3 | MediaPipe 세그멘테이션 통합 | 배경 제거 마스크 육안 검증 |
| Phase 4 | 오행별 배경 합성 (Canvas) | 오행 5종 모두 합성 결과 확인 |
| Phase 5 | Blob 업로드 + QR 생성/표시 | QR 스캔 → 다운로드 페이지 정상 로드 |
| Phase 6 | 개인정보 동의 문구 + 만료(TTL) 정책 + 정리 크론 | 만료 후 접근 시 안내 메시지 노출 |
| Phase 7 | 키오스크 UX (유휴 타임아웃, 애니메이션, 재촬영) | 연속 방문 시나리오 수동 테스트 |

## 6. 성공 기준

- [ ] 생년월일 입력 → 오행 분석까지 기존 `saju/analyze` 로직과 일관된 결과 반환
- [ ] 카메라 권한 획득 → 촬영 → 세그멘테이션 → 합성까지 5초 내 완료 (모바일 중급 기기 기준)
- [ ] 오행 5종 배경 모두 합성 품질 육안 검수 통과
- [ ] QR 스캔 시 다운로드 페이지 정상 진입, 이미지 저장 가능
- [ ] 만료된 사진은 접근 시 삭제 안내로 대체
- [ ] 모바일 세로 화면(375~430px) 기준 키오스크 UI 정상 동작
- [ ] 방문자 얼굴 사진에 대한 보관 기간/삭제 정책 고지 완료

## 7. 리스크 및 고려사항

| 리스크 | 대응 방안 |
|--------|-----------|
| 세그멘테이션 품질 (머리카락 경계, 역광) | 마스크 가장자리 페더링(블러) 처리, 매장 조명 가이드 문서화 |
| iOS Safari 카메라 권한/HTTPS 제약 | 프로덕션 HTTPS 필수, 권한 거부 시 안내 화면 제공 |
| 얼굴 사진 개인정보 이슈 | TTL(예: 24~48시간) 자동 삭제 + 명시적 동의 화면 |
| 다중 방문자 연속 사용 시 상태 잔류 | 결과 화면 후 일정 시간 경과 시 자동으로 인트로 초기화 |
| 배경 이미지 생성 품질/일관성 | 런타임 AI 생성 대신 사전 검수된 정적 이미지 사용 (안정성·속도 우선) |
| 네트워크 불안정 시 업로드 실패 | 업로드 실패 시 재시도 버튼 + 로컬 canvas 결과 임시 보존 |
