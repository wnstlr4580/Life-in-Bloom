# [Plan] 오행 포토부스 (키오스크)

> 인생네컷 스타일의 모바일 웹 키오스크 — 생년월일 입력 → 오행 분석 → 네컷 촬영 → 오행에 어울리는 꽃 배경 합성 → QR로 상세 사주 풀이·사진 저장
> 기존 `인생내꽃.plan.md`의 **Feature D (오프라인 포토부스 연동)** 를 구체화한 문서. 기존 PC 쇼핑몰과는 별개의 모바일 전용 경험으로 설계한다.

---

## 1. 개요 (Overview)

### 배경

기존 인생내꽃 플랫폼은 PC 웹 쇼핑몰 중심이며, `saju/` 페이지에서 생년월일 기반 오행 분석과 꽃 추천을 이미 제공한다. 이번 기능은 그 오행 분석 로직(`lib/saju.ts`)을 재사용하되, 매장 현장의 키오스크(태블릿/모바일 브라우저)에서 동작하는 **별도의 모바일 웹 경험**을 새로 만든다.

- 참고 모델: "인생네컷" 등 즉석 포토부스 — 다만 그린스크린 촬영이 아니므로, 배경 합성은 소프트웨어적으로 처리한다.
- 실제 인생네컷처럼 **총 4장을 촬영해 세로 스트립 한 장으로 완성**한다.
- 어떤 꽃이 나올지는 촬영 중에는 알려주지 않고, 합성이 끝난 결과 화면에서 처음 공개한다 (기대감을 살리는 연출).
- 방문객은 로그인 없이 즉석에서 체험하며, QR을 스캔하면 기존 `/saju` 페이지로 연결되어 상세 사주 풀이와 함께 사진을 저장할 수 있다. (구매/장바구니 연동은 이번 범위에 포함하지 않음 — 향후 과제로 분리)

### 핵심 플로우

```
[인트로 화면] → [생년월일 입력] → [오행 분석 (재사용: lib/saju.ts)]
     ↓
[네컷 촬영 — 컷마다 3-2-1 카운트다운, 꽃 배경은 비공개]
     ↓
[컷별 인물 분리 + 오행 꽃 배경 합성] → [네컷 스트립 조립]
     ↓
[결과 공개 — 꽃 이름·꽃말 최초 공개] → [QR 코드 생성] → [일정 시간 후 인트로로 자동 복귀]
     ↓
[방문객이 QR 스캔] → [/saju 페이지로 딥링크 — 자동 분석 + 사진 저장 + 상세 사주 풀이]
```

### 기존 Feature D와의 관계

| 구분 | 기존 Feature D (plan 문서) | 이번 기능 (오행 포토부스) |
|------|---------------------------|--------------------------|
| 트리거 | 구매 후 QR 스캔 (구매자 전용) | 누구나 바로 체험 (비회원, 비구매) |
| 배경 | "구매한 꽃"을 배경으로 표시 | 오행 분석 결과에 맞는 꽃 배경을 합성 생성 |
| 결과물 | 매장 하드웨어로 촬영 지원 | 모바일 웹에서 네컷 촬영·합성·QR까지 전부 처리 |
| 목적 | 구매 연계 체험 | 유입/바이럴용 단독 체험 (구매 연동은 향후 과제) |

두 기능은 배타적이지 않으며, 이번 기능이 먼저 단독으로 동작하도록 만들고, 이후 "이 꽃 배경으로 꽃다발 주문하기" 같은 CTA를 붙여 Feature D와 합류시킬 수 있다.

## 2. 핵심 기능

### Feature A: 생년월일 → 오행 분석 (재사용)

`lib/saju.ts`의 `analyzeOhaeng()`을 그대로 재사용. 키오스크에서는 터치 친화적인 간소화 입력폼(년/월/일)만 새로 만든다 — 시간·이름·도시는 받지 않아 일주(日柱) 오행 하나만 정확히 산출한다.

### Feature B: 네컷 촬영

- `getUserMedia`로 전면 카메라 기본 활성화 (후면 전환 옵션)
- 실제 인생네컷처럼 **총 4컷**, 컷마다 3-2-1 카운트다운 후 자동 캡처
- 첫 컷만 사용자가 직접 시작하고, 이후 3컷은 짧은 텀을 두고 자동으로 이어서 촬영
- 촬영 중에는 오행/꽃 정보를 전혀 노출하지 않는다 — "어떤 꽃이 나올지 기대해주세요" 정도의 문구만 표시

### Feature C: 인물 분리 + 오행 꽃 배경 합성 + 스트립 조립

- 클라이언트 사이드 인물 세그멘테이션(브라우저 내 WASM 모델)으로 컷마다 인물만 분리
- 오행별로 미리 정해둔 꽃 배경 이미지 위에 4컷 모두 동일하게 합성 (Canvas API)
- 4컷을 세로 스트립 하나로 조립하고, 하단에 꽃 이름·꽃말·오늘 날짜·"인생내꽃" 로고를 그려 넣음
- 상세 기술 방식은 `오행포토부스.design.md` 참고

### Feature D: 오행별 꽃/꽃말 프리셋

- DB 조회 없이, 오행마다 꽃 1종 + 색상 + 꽃말을 고정값으로 미리 정의 (기존 `lib/saju.ts`의 `FLOWER_BY_STAGE.일주`, `/custom` 페이지의 꽃 오행 태깅과 동일한 조합 재사용)
- 목=핑크 튤립·사랑의 고백, 화=빨간 장미·열정적인 사랑, 토=노란 국화·고결한 마음, 금=흰 백합·순수한 사랑, 수=파란 수국·진심

### Feature E: 결과 공개 + QR → 상세 사주 풀이 연결

- 네컷 합성이 끝나면 키오스크 화면에서 꽃 이름·꽃말을 처음 공개
- 완성된 스트립 이미지를 서버에 업로드하고, QR 코드를 생성 (기존 `qrcode` / `react-qr-code` 의존성 재사용)
- **QR은 별도의 다운로드 전용 페이지가 아니라 기존 `/saju` 페이지로 딥링크**한다 — 생년월일을 쿼리 파라미터로 넘겨 자동으로 오행 분석을 실행하고, 촬영한 네컷 사진도 그 페이지에 함께 보여준다
- `/saju` 페이지에는 키오스크에서 입력하지 않은 태어난 시간을 추가 입력해 더 정확한 사주 풀이(시주 포함)를 볼 수 있는 선택지도 그대로 제공된다 (기존 폼 재사용)
- 저장된 사진은 일정 기간 후 자동 삭제 (개인정보 보호)

### 이번 범위에 포함하지 않는 것

- 촬영 전 개인정보 동의 화면 (요청에 따라 제외 — 필요 시 향후 추가)
- 구매/장바구니 연동, 결제 연동
- 회원가입/로그인 연동 (완전 비회원 플로우)

## 3. 기술 스택 (기존 스택에 추가)

| 분류 | 선택 | 이유 |
|------|------|------|
| 인물 세그멘테이션 | `@mediapipe/tasks-vision` (Selfie Segmenter) | 브라우저 WASM 실행, 무료, 단일 프레임 처리 속도가 빨라 키오스크 회전율에 적합 |
| 이미지 합성 | Canvas API (직접 구현) | 마스크 알파 합성 + 네컷 스트립 조립에 세밀한 제어 필요 (html2canvas는 DOM 캡처용이라 부적합) |
| 결과 업로드 | `@vercel/blob` | 이미 `BLOB_READ_WRITE_TOKEN` 환경변수 존재, 기존 스택과 일관성 |
| QR 코드 | `qrcode` / `react-qr-code` (기존 의존성) | 이미 설치되어 있음 |
| DB 조회 | Supabase JS client (`lib/supabase.ts`) | 기존 `app/api/saju/analyze`가 Prisma가 아닌 Supabase client로 조회하는 패턴을 따름 |

## 4. 프로젝트 구조 (예상)

```
app/
├── (kiosk)/                        # 헤더/장바구니 없는 풀스크린 모바일 레이아웃
│   ├── layout.tsx
│   └── kiosk/
│       └── page.tsx                # 인트로 → 생년월일 → 네컷 촬영 → 합성 → 결과, 한 페이지 내 단계 전환
├── (shop)/saju/page.tsx            # 기존 페이지 — 쿼리 파라미터(birthDate, kiosk)로 키오스크 결과와 연결 (수정)
```

## 5. 개발 단계 (Phases)

| Phase | 내용 | 검증 기준 |
|-------|------|-----------|
| Phase 1 | 생년월일 입력 → 오행 분석 재사용 화면 | 오행 결과가 `lib/saju.ts`와 동일하게 도출 |
| Phase 2 | 네컷 촬영 (컷마다 카운트다운, 자동 연속 촬영) | 4장 모두 canvas에 정상 캡처 |
| Phase 3 | MediaPipe 세그멘테이션 + 컷별 배경 합성 | 배경 제거 마스크 육안 검증 |
| Phase 4 | 네컷 스트립 조립 (꽃 이름·꽃말·날짜·로고) | 오행 5종 모두 스트립 결과 확인 |
| Phase 5 | Blob 업로드 + QR 생성 → `/saju` 딥링크 | QR 스캔 → `/saju` 자동 분석 + 사진 표시 정상 동작 |
| Phase 6 | `/saju` 페이지 "더 자세히" 재분석 도선 (시간 입력) | 시간 추가 입력 후 시주 포함 결과로 갱신 확인 |
| Phase 7 | 만료(TTL) 정책 + 정리 크론 | 만료 후 접근 시 안내 메시지 노출 |
| Phase 8 | 키오스크 UX (유휴 타임아웃, 재촬영) | 연속 방문 시나리오 수동 테스트 |

## 6. 성공 기준

- [ ] 생년월일 입력 → 오행 분석까지 기존 `saju/analyze` 로직과 일관된 결과 반환
- [ ] 네컷 촬영 중에는 오행/꽃 정보가 전혀 노출되지 않음
- [ ] 카메라 권한 획득 → 4컷 촬영 → 세그멘테이션 → 합성 → 스트립 조립까지 무리 없이 완료
- [ ] 오행 5종 모두 꽃/꽃말/배경 합성 품질 육안 검수 통과
- [ ] QR 스캔 시 `/saju` 페이지로 이동해 자동 분석 결과와 네컷 사진이 함께 표시됨
- [ ] `/saju` 페이지에서 시간 추가 입력 시 시주 포함 결과로 정상 갱신
- [ ] 만료된 사진은 접근 시 삭제 안내로 대체
- [ ] 모바일 세로 화면(375~430px) 기준 키오스크 UI 정상 동작

## 7. 리스크 및 고려사항

| 리스크 | 대응 방안 |
|--------|-----------|
| 세그멘테이션 품질 (머리카락 경계, 역광) | 마스크 가장자리 페더링(블러) 처리, 매장 조명 가이드 문서화 |
| iOS Safari 카메라 권한/HTTPS 제약 | 프로덕션 HTTPS 필수, 권한 거부 시 안내 화면 제공 |
| 얼굴 사진 개인정보 이슈 | TTL(48시간) 자동 삭제. 촬영 전 별도 동의 화면은 이번 범위에서 제외했으므로, 매장 내 안내판 등 오프라인 고지 수단 검토 필요 |
| 네컷 촬영 도중 이탈/재촬영 | "다시 촬영" 시 4컷 전체를 다시 찍는 방식으로 단순화 (컷 단위 재촬영은 향후 과제) |
| 배경 이미지 품질/일관성 | 런타임 AI 생성 대신 사전 검수된 정적 이미지 사용 (안정성·속도 우선) |
| 네트워크 불안정 시 업로드 실패 | 업로드 실패 시 재시도 버튼 + 로컬 canvas 결과 임시 보존 |
| `/saju` 페이지 변경으로 인한 회귀 | 기존 폼 제출 플로우(비키오스크 사용자)는 그대로 유지, 쿼리 파라미터 존재 시에만 자동 분석 추가 — 회귀 테스트 필요 |
