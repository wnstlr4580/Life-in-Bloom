# [Plan] 판매처 등록 및 역할별 계정

> 일반 사용자·판매자·관리자의 가입과 이용 영역을 분리하고, 판매처 심사·상품·개별 꽃 재고·서비스 노출을 관리한다.

## 1. 목표

- 일반 사용자와 판매자는 처음 가입할 때부터 서로 다른 계정 유형으로 생성한다.
- 관리자는 공개 가입을 제공하지 않고 기존 관리자가 권한을 부여한다.
- 판매자는 가입과 동시에 사업자·판매처 정보를 제출하고 관리자 승인을 기다린다.
- 승인된 판매자만 완제품 상품, 개별 꽃 재고, 판매처 주문을 관리할 수 있다.
- 판매자는 가입할 때 서비스 참여 여부를 신청하고, 가입 후 판매자센터에서 언제든 변경할 수 있다.

## 2. 역할

| 역할 | 가입 | 기본 진입점 | 주요 기능 |
|---|---|---|---|
| 일반 사용자 (`CUSTOMER`) | 이메일·카카오·구글 | `/mypage` | 주문, 리뷰, 포인트, 찜, 오행 정보 |
| 판매자 (`SELLER`) | 판매자 전용 이메일 가입 | `/seller` | 판매처 정보, 완제품, 개별 꽃 재고, 판매 주문 |
| 관리자 (`ADMIN`) | 공개 가입 없음 | `/admin` | 판매자 심사, 전체 상품·주문·회원·권한 관리 |

역할은 상호 배타적으로 운영한다. 판매자가 구매 기능을 이용하려면 일반 사용자 계정을 별도로 사용한다. 동일 이메일은 전체 `User`에서 중복 사용할 수 없다.

## 3. 가입 진입 구조

```text
/signup
├─ 일반 사용자 회원가입 → /signup/customer
│  ├─ 카카오
│  ├─ 구글
│  └─ 이메일
└─ 판매자 회원가입 → /signup/seller
   ├─ 계정 정보
   ├─ 사업자 정보
   ├─ 판매처 정보
   ├─ 서비스 참여 설정
   └─ 약관 동의 → 심사 대기
```

## 4. 판매자 가입 정보

### 필수

| 분류 | 항목 | 비고 |
|---|---|---|
| 계정 | 로그인 이메일 | 인증 및 알림 수신 |
| 계정 | 비밀번호·비밀번호 확인 | 8자 이상, 서버에서 해시 저장 |
| 담당자 | 담당자명 | 운영 연락 담당자 |
| 담당자 | 휴대전화번호 | 본인 확인은 후속 단계에서 연동 가능 |
| 사업자 | 상호명(법적 사업자명) | 사업자등록증 표기값 |
| 사업자 | 사업자등록번호 | 숫자 정규화, 중복 가입 방지 |
| 사업자 | 대표자명 | 사업자등록증 표기값 |
| 사업자 | 업태·종목 | 예: 도소매 / 생화·화훼 |
| 판매처 | 마켓명(고객 노출명) | 상품 카드와 지도에 표시 |
| 판매처 | 판매처 유형 | 꽃집 / 농가 / 도매 / 기타 |
| 판매처 | 우편번호·도로명주소·상세주소 | 지도 및 거리 계산에 사용 |
| 판매처 | 위치 좌표 | 주소 검색 결과로 위도·경도 저장 |
| 정산 | 정산 계좌 은행·계좌번호·예금주 | 초기에는 암호화 또는 별도 보안 저장 검토 |
| 증빙 | 사업자등록증 | Supabase Storage 비공개 버킷 |
| 동의 | 판매자 이용약관·개인정보·정산 동의 | 동의 시각과 약관 버전 저장 |

### 선택

| 분류 | 항목 | 비고 |
|---|---|---|
| 판매처 | 대표 전화번호 | 고객 문의용 |
| 판매처 | 소개 문구 | 판매처 상세와 지도 팝업 |
| 판매처 | 대표 이미지·로고 | Supabase Storage |
| 판매처 | 영업시간·휴무일 | 지도 및 주문 가능 안내 |
| 사업자 | 통신판매업 신고번호 | 온라인 판매 정책에 따라 승인 필수 조건으로 변경 가능 |
| 서비스 | 완제품 판매 | 기본값 `true` |
| 서비스 | 나만의 꽃다발 주문하기 참여 | 가입 시 신청 가능 |
| 서비스 | 직접 만든다면? 참여 | 가입 시 신청 가능 |

쿠팡 등 오픈마켓의 일반적인 입점 흐름처럼 계정 생성 뒤 사업자 인증, 상품 등록, 배송·정산 준비로 이어지는 구조를 참고한다. 다만 인생내꽃은 가입 폼에서 심사에 필요한 기본 사업자·판매처 정보를 한 번에 제출한다.

## 5. 판매자 상태

```text
PENDING(신청)
→ UNDER_REVIEW(검토중)
→ APPROVED(승인)
   또는 REJECTED(반려)

REJECTED → 정보 수정·재제출 → PENDING
APPROVED → 운영상 필요 시 SUSPENDED(이용정지)
```

- `SELLER` 역할만으로 판매 API를 허용하지 않는다.
- 모든 판매 기능은 `Seller.status = APPROVED`를 함께 검사한다.
- 심사 상태와 반려 사유는 `/seller` 첫 화면에 표시한다.

## 6. 역할별 마이페이지

### 일반 사용자 `/mypage`

기존 구현을 유지한다.

- 프로필·닉네임
- 보유 포인트
- 주문 내역과 후기
- 위시리스트·알림 설정
- 나의 오행 분석 정보
  - 이름
  - 성별
  - 생년월일
  - 양력/음력
  - 태어난 시간
  - 태어난 지역

### 판매자센터 `/seller`

- 홈: 심사 상태, 처리할 주문, 품절 임박 재고
- 판매처 정보
- 서비스 참여 설정
- 완제품 상품 관리
- 개별 꽃 재고 관리
- 주문·배송 관리
- 정산 관리(후속)

`완제품 상품`은 꽃다발·화분·선물세트처럼 고객이 그대로 구매하는 `Product`다.
`개별 꽃 재고`는 장미 20송이, 튤립 12송이처럼 꽃다발 조합과 “직접 만든다면?” 재료 매칭에 사용하는 `SellerStock`이다.
### 관리자센터 `/admin`

- 판매자 가입 심사와 승인·반려
- 판매처 상태 관리
- 전체 완제품·재고·주문 관리
- 일반 사용자·판매자 계정 조회
- 관리자 권한 부여·회수와 감사 로그

최초 관리자는 Supabase SQL로 지정한다. 이후 관리자 추가는 기존 관리자만 수행하며 공개 관리자 가입 페이지는 만들지 않는다.

## 7. 서비스 참여 설정

판매자는 가입 시 아래 항목을 선택하고, 승인 후에도 `/seller/settings/services`에서 자유롭게 변경할 수 있다.

| 설정 | 효과 |
|---|---|
| 완제품 판매 | 판매자의 활성 `Product`를 마켓플레이스에 노출 |
| 나만의 꽃다발 주문하기 | 선택한 꽃을 제작·배송할 판매처 후보로 노출 |
| 직접 만든다면? | 개별 꽃 구매처 및 예상 가격 후보로 노출 |

변경은 즉시 저장하되 실제 노출에는 다음 공통 조건을 모두 적용한다.

- 판매자 상태가 `APPROVED`
- 해당 서비스 설정이 활성
- 판매처가 운영 중
- 필요한 상품 또는 개별 꽃 재고가 존재

서비스 참여를 끄더라도 기존 주문과 주문 이력은 유지하며 신규 매칭과 신규 노출만 중단한다.

## 8. 구현 단계

1. 역할·판매처·심사·서비스 설정 Supabase 스키마
2. 세션에 `role`, `sellerStatus` 반영 및 역할별 접근 제어
3. 가입 유형 선택과 판매자 가입 폼
4. 판매자 심사 상태 화면과 판매자센터 뼈대
5. 관리자 판매자 승인 화면
6. 완제품에 `sellerId` 연결
7. 개별 꽃 재고와 서비스 매칭
