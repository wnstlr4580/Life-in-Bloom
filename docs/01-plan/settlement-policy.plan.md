# 인생내꽃 판매자 정산 정책 및 운영 기획안

## 1. 문서 목적

인생내꽃의 다중 판매처 주문에서 결제대금의 귀속, 플랫폼 수수료, 구매확정, 환불, 판매자 지급 절차를 정의한다. 이 문서는 개발·운영·판매자 계약서 작성의 기준안이며, 실제 서비스 개시 전 PG사·지급대행사·세무사·법률 전문가의 검토를 받아야 한다.

## 2. 권장 사업 구조

- 인생내꽃은 꽃집·농가와 구매자를 연결하는 통신판매중개 플랫폼으로 운영한다.
- 상품의 실제 판매 주체와 품질·배송 책임 주체는 입점 판매자다.
- 카드결제는 인생내꽃이 계약한 PG를 통해 처리한다.
- PG사의 결제사 정산과 판매자에게 지급하는 파트너 정산은 별도 단계로 관리한다.
- 판매자 지급은 플랫폼이 고객자금을 임의 보관·운용하는 방식이 아니라 PG/정산 전문사의 지급대행 서비스를 우선 사용한다.
- 현재 연동 중인 포트원을 기준으로 파트너 정산 자동화 또는 동등한 지급대행 서비스를 검토한다.

## 3. 자금 흐름

```text
구매자 카드결제
  → 카드사 승인
  → PG 결제 처리
  → PG가 계약된 정산계정으로 결제사 정산
  → 인생내꽃이 주문별 판매자 정산금 확정
  → 지급대행사가 판매자 등록계좌로 송금
```

결제 승인 시점에 판매자 계좌로 바로 입금하지 않는다. 배송·취소·환불 가능성이 있으므로 구매확정까지 `미정산금`으로 관리한다.

## 4. 기본 정책

| 항목 | 정책 |
|---|---|
| 정산 기준 | 주문상품별 구매확정 |
| 자동 구매확정 | 배송 완료 후 7일 |
| 지급 주기 | 매주 금요일 |
| 기본 중개수수료 | 상품금액의 10% |
| 수수료 부가세 | 중개수수료의 10%, 판매자 정산금에서 별도 차감 |
| 수수료 적용 대상 | 상품금액, 배송비 제외 |
| 배송비 귀속 | 판매자 정산금에 포함 |
| PG 수수료 | 초기에는 플랫폼 부담 |
| 플랫폼 포인트 | 초기에는 플랫폼 부담 |
| 판매자 부담 쿠폰 | 별도 계약 또는 프로모션 동의가 있는 경우만 차감 |
| 정산 전 취소 | 정산 대상에서 제외 |
| 정산 후 환불 | 차기 정산 조정금에서 차감 |
| 음수 정산 | 다음 회차로 이월, 임의 계좌 출금 금지 |

판매처별 수수료율은 관리자가 0~100% 범위에서 변경할 수 있다. 변경된 수수료율은 신규 주문부터 적용하며 이미 생성된 주문의 확정 수수료는 소급 변경하지 않는다.

## 5. 정산 계산식

```text
상품 총액 = 상품 단가 × 수량

정산 기준금액
= 상품 총액
+ 판매자 귀속 배송비
- 판매자 부담 할인액

중개수수료 = 상품 총액 × 판매처 수수료율
중개수수료 VAT = 중개수수료 × 10%

최종 정산금
= 정산 기준금액
- 중개수수료
- 중개수수료 VAT
- 판매자 부담 PG 수수료
- PG 수수료 VAT
+ 정산 조정금
```

### 계산 예시

- 상품금액: 50,000원
- 판매자 귀속 배송비: 5,000원
- 중개수수료율: 10%
- PG 수수료: 플랫폼 부담
- 할인 없음

```text
상품금액                    50,000원
배송비                      +5,000원
중개수수료                  -5,000원
중개수수료 VAT                -500원
판매자 최종 정산금          49,500원
플랫폼 중개수수료 매출       5,000원
```

PG 수수료와 플랫폼 운영비는 중개수수료 매출에서 플랫폼이 부담한다.

## 6. 상태 정의

| 상태 | 의미 | 전환 조건 |
|---|---|---|
| `WAITING` | 구매확정 대기 | 결제·배송 중 또는 배송 완료 후 7일 이내 |
| `READY` | 정산 예정 | 구매자 직접 확정 또는 자동 구매확정 |
| `HOLD` | 정산 보류 | 분쟁, 환불 요청, 계좌 오류, 이상거래 확인 |
| `PAID` | 지급 완료 | 지급대행 또는 계좌이체 성공 확인 후 관리자 기록 |
| `CANCELLED` | 정산 취소 | 주문 취소·전액 환불 |

```text
결제완료 → 상품준비 → 배송중 → 배송완료
                              ↓
                       직접/자동 구매확정
                              ↓
                         정산예정(READY)
                         ↙             ↘
                    보류(HOLD)       지급완료(PAID)
```

## 7. 구매확정과 지급일

- 구매자는 배송 완료 후 직접 구매확정할 수 있다.
- 구매확정을 누르지 않으면 배송 완료일로부터 7일 뒤 자동 확정한다.
- 구매확정 후 도래하는 다음 금요일을 지급 예정일로 계산한다. 금요일에 확정된 건은 다음 주 금요일에 지급한다.
- 지급 예정일이 지난 `READY` 건만 지급할 수 있다.
- 금요일이 공휴일인 경우 실제 지급대행사의 영업일 정책에 따라 전·후 영업일로 조정하는 기능은 후속 연동에서 처리한다.

## 8. 취소·환불·분쟁

### 정산 전 전액 취소

- 주문상품 상태를 `CANCELLED`로 변경한다.
- 정산금은 0원으로 만들고 지급 대상에서 제외한다.
- 구매 포인트와 따라 구매 포인트를 기존 포인트 정책에 따라 회수한다.
- 실제 PG 결제취소 성공 여부와 내부 주문 취소 상태를 대사해야 한다.

### 부분 취소

- 주문 전체가 아닌 `OrderItem` 단위로 취소한다.
- 취소한 상품의 배송비 배분액과 할인 분담액을 다시 계산한다.
- 부분취소 PG 응답 금액과 내부 환불 금액이 일치해야 한다.

### 정산 후 환불

- 이미 지급된 정산 기록을 수정하거나 삭제하지 않는다.
- 환불액을 음수 `adjustmentAmount`로 새 장부에 기록해 다음 정산에서 상계한다.
- 다음 정산금보다 환불 조정액이 크면 음수 잔액을 다음 회차로 이월한다.
- 판매자 계좌에서 자동 인출하지 않는다.

### 보류

- 미배송, 소비자 분쟁, 계좌 명의 불일치, 이상거래가 있으면 관리자가 사유를 기록하고 `HOLD`로 변경한다.
- 보류 해제 시 다음 금요일을 새 지급 예정일로 설정한다.
- 모든 보류·해제·지급 처리는 관리자 감사로그에 남긴다.

## 9. 배송비·쿠폰·포인트 정책

### 배송비

- 현재는 주문 배송비 전액을 상품금액 비율에 따라 주문상품에 배분한다.
- 여러 판매처 상품을 한 주문에서 결제하는 경우 실제 배송이 판매처별로 발생하므로 장기적으로는 판매처별 배송비를 결제 단계에서 계산해야 한다.
- 중개수수료는 배송비에 적용하지 않는다.

### 포인트

- 초기에는 인생내꽃이 발행한 포인트 비용을 플랫폼이 부담한다.
- 판매자 정산 기준은 고객의 포인트 사용 전 상품 정상가를 사용한다.
- 판매자 부담 프로모션을 도입할 때만 계약된 분담률을 `discountShare`로 기록한다.

### 쿠폰

- 플랫폼 쿠폰: 플랫폼 부담
- 판매자 쿠폰: 판매자 부담
- 공동 프로모션: 사전 동의한 분담률에 따라 나눔

## 10. 세무·회계 원칙

- 상품 매출 전체를 플랫폼 매출로 단정하지 않는다. 통신판매중개 구조에서는 판매자의 상품 매출과 플랫폼의 중개수수료 매출을 구분한다.
- 플랫폼은 판매자에게 부과한 중개수수료와 그 부가세를 구분해 기록한다.
- 세금계산서 발행 방향(정발행/역발행), 배송비 세무처리, 쿠폰 분담금 처리는 세무사 검토 후 확정한다.
- 주문별 장부 금액은 지급 후에도 덮어쓰지 않고 조정 내역을 별도로 남긴다.
- PG 거래대사 결과와 내부 결제·취소·정산 장부를 매일 비교한다.

## 11. 계좌·개인정보·권한

- 판매자 가입 시 사업자정보, 예금주, 정산계좌를 수집한다.
- 사업자 또는 대표자 명의 계좌 여부를 지급대행 등록 과정에서 검증한다.
- 판매자 화면에서는 자신의 정산 내역만 조회할 수 있다.
- 일반 관리자는 계좌번호 전체를 볼 필요가 없으면 마스킹한다.
- 지급 권한과 판매자 승인 권한은 실제 운영 단계에서 분리하는 것을 권장한다.
- 지급완료 처리는 지급대행 성공 응답 또는 은행 이체 결과를 확인한 뒤 수행한다.

## 12. 현재 구현 범위

### 구현됨

- 판매처별 수수료율
- 상품별 수수료와 수수료 VAT 계산
- 판매자 귀속 배송비 배분
- PG 수수료·할인분담금·조정금 장부 필드
- 구매자 직접 구매확정
- 배송 완료 7일 후 자동 구매확정 Cron
- 금요일 지급 예정일 계산
- 판매자 정산 요약과 상세내역
- 관리자 정산 예정·보류·지급완료 처리
- 관리자 처리 감사로그

### 외부 계약 후 구현

- 포트원 파트너 등록 및 계약 API
- 지급대행 계좌 검증
- 실제 일괄 송금 API
- 송금 실패 재시도와 실패 사유 저장
- PG 결제·취소 거래대사
- 세금계산서 정발행/역발행
- 공휴일 영업일 계산
- 정산 후 환불용 별도 조정 장부

현재 관리자 화면의 `지급 완료`는 실제 송금을 실행하지 않고 지급 결과를 내부 장부에 기록하는 기능이다. 지급대행 연동 전에는 반드시 실제 이체 완료를 확인한 후 사용해야 한다.

## 13. API 및 배치

| 경로 | 역할 |
|---|---|
| `POST /api/orders/items/:id/confirm` | 구매자 직접 구매확정 |
| `GET /api/cron/settlements` | 배송 완료 7일 경과 주문 자동 구매확정 |
| `GET /api/seller/settlements` | 판매자 정산 조회 |
| `GET /api/admin/settlements` | 관리자 전체 정산 조회 |
| `PATCH /api/admin/settlements` | 보류·해제·지급완료·수수료율 변경 |

Cron은 매일 실행하며 `Authorization: Bearer {CRON_SECRET}`가 필요하다.

- [ ] 사용자 직접 구매확정과 중복 요청 방지
- [ ] 배송 완료 7일 후 자동 구매확정

- [ ] 지급 예정일 전 지급 차단
- [ ] 정산 보류·해제 및 감사로그
- [ ] 정산 전 주문 취소
- [ ] 부분 취소와 배송비 재배분

- [ ] 판매처별 수수료율 변경이 신규 주문에만 적용되는지 확인
